# PN-A2DP v0.1.0.30 — experimental prerelease

**Application 0.1.0.30 · custom driver 0.1.0.18 · Windows x64**

Choose **Windows mode** for use without Test Mode. The separate **Test Mode**
package contains a self-signed development kernel driver; it is **not a
Microsoft-signed production release**. PN-A2DP applications and installers currently
have no public Authenticode publisher signature and may show a reputation warning.

No signing private key, local audio capture, diagnostic log or PDB is included.

## What changed

- Faster adaptive quality recovery: 30 seconds for the first upward step, then
  10, then 5 during continuous healthy traffic. Quick relapses require 60 seconds
  before retrying; receiver/configured quality limits still apply.
- More persistent reconnect attempts and codec-host worker retry delays, plus
  session reset handling on power resume.
- **Quality > Events** explains observed bitrate and stream changes. An explicit
  **Use adaptive SBC** option can appear after persistent fixed-rate aptX trouble.
- Protected installation/service paths reject unsafe ownership, permissions,
  redirected paths and hard-linked payload files.
- aptX/LDAC input-validation fixes, more encoder flush/reconfiguration tests,
  installer version checks and complete codec redistribution artifacts.

## Test Mode installation

Read the [complete setup and recovery guide](https://github.com/patnawa/PN-A2DP/blob/v0.1.0.30/docs/17-test-mode-release-guide.md)
before changing boot settings. These steps reduce Windows protections and are for
development testing. If device encryption/BitLocker is enabled, prepare the
recovery key and follow the PC's firmware-change procedure.

1. Verify installer/certificate SHA-256 values against `SHA256SUMS.txt`.
2. For **this PN development build**, prepare **Secure Boot OFF** and **Memory
   Integrity OFF**. Use Windows mode if you want to keep the normal protections.
3. In administrator PowerShell, run `bcdedit /set testsigning on`, then **restart
   manually**. The setting must be active in the running session.
4. Inspect `PN-A2DP-Test-Certificate.cer`. Its SHA-1 thumbprint must be
   **`12EE1EAE30E0DEACCFB2870C393D3C148B1E210E`** and it must have no private key.
   If you intend to trust it for testing, run these commands from the download
   folder in administrator PowerShell:

   ```powershell
   certutil -addstore Root .\PN-A2DP-Test-Certificate.cer
   certutil -addstore TrustedPublisher .\PN-A2DP-Test-Certificate.cer
   ```

5. Pause playback, close the control panel and launch:

   ```powershell
   .\PN-A2DP-0.1.0.30-testmode-setup.exe --allow-test-driver
   ```

6. Keep the protected Program Files destination and select the receiver(s) to
   switch. After any requested restart, check the Driver requirements, select the
   receiver in Windows Sound and use **Check my audio**.

Setup does not enable Test Mode, import trust or restart Windows automatically.
Adding a certificate or accepting an installer warning does not make this driver
load in normal Windows mode. The Memory Integrity-off requirement is specific to
this validated PN development configuration; it is not a universal rule for every
test-signed driver.
[Microsoft Test Mode guidance](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/the-testsigning-boot-configuration-option),
[test-certificate guidance](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/installing-test-certificates).

**To leave Test Mode:** switch every PN device to **Driver > Use Windows mode**
or uninstall PN-A2DP first. Confirm Windows-driver playback, then run
`bcdedit /set testsigning off` as administrator and restart. Restore Secure Boot,
Memory Integrity and any suspended BitLocker protection. The full guide gives
the exact commands for removing only this development certificate.

## Validation and limitations

- The bundled driver is byte-identical to the installed Sony-tested driver.
- This release packaging run passed **21 software groups**, **7 Windows-mode**
  checks and **7 signing-policy** checks. The preceding implementation run passed
  **29 groups including AddressSanitizer**, plus **31 live KS checks**.
- Sony CMT-SBT40D on the tested Qualcomm adapter: **48 kHz / 672 kbps SBC**,
  three software reconnects in **2.18–2.60 seconds**, no new transport errors in
  the observed windows, retained preferences, and user-confirmed clear music,
  normal loudness and functioning Windows volume/mute.
- Physical AAC/aptX/LDAC interoperability, confirmed power-cycle disconnection,
  sleep/wake, host-encoded recovery/fallback, broader hardware and LDAC independent
  decoding remain unverified. Driver Verifier, HLK and production signing remain
  outstanding. Codec source inclusion does not establish patent clearance or
  product certification.

Report the version, receiver/adapter model and reproduction steps when reporting
a problem. **Quality > Export diagnostics** produces an allowlisted local report;
review it before sharing. Neither clean transport counters nor encoder tests prove
universal sound quality or receiver compatibility.
