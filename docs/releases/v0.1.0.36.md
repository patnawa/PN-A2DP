# PN-A2DP v0.1.0.36 — experimental prerelease

**Application 0.1.0.36 · custom driver 0.1.0.23 · Windows x64**

Choose **Windows mode** for use without Test Mode. The separate **Test Mode**
package contains a self-signed development kernel driver; it is **not a
Microsoft-signed production release**. It is signed with the same development
certificate as v0.1.0.30 and v0.1.0.34. PN-A2DP applications and installers currently
have no public Authenticode publisher signature and may show a reputation warning.

## What's new

**Audio quality (driver 0.1.0.23)**

- **Your Windows sound format is now used.** Every earlier PN driver made Windows'
  shared-mode engine use the driver's first listed format (normally 48 kHz) instead
  of the one chosen under **Sound > device > Properties > Advanced > Default
  Format**. Windows now opens the format you
  choose, and a receiver that supports that rate plays it natively (on the
  EDIFIER MR5: LDAC at 44.1 kHz, 909 kbps).
- **Sample-rate converter.** When the receiver lacks the Windows rate, or Windows
  changes its format after playback has started, the driver converts between 44.1,
  48, 88.2 and 96 kHz Windows formats and the codec's 44.1 or 48 kHz. It is fixed
  point, linear phase and alias-free: at least 122 dB rejection of every alias and
  image, a passband flat within 0.00002 dB to 20 kHz, THD+N about -140 dB
  from 24-bit sources and about -149 dB from float, at most about 2 ms of added latency
  and about 0.5 % of one CPU core in the worst case. Streams at the Windows rate
  are not touched (bit-identical to v0.1.0.34).
- **Format changes during playback no longer reconnect.** Switching Windows between
  44.1 and 48 kHz while music plays keeps the Bluetooth stream; the converter
  bridges the new rate (on hardware, the 44.1 to 48 kHz direction was tested). Before the first sound of a stream, the driver still moves
  the stream to the Windows rate, so native paths are kept.
- **The best codec the receiver offers is used** even when it lacks the Windows
  rate (for example aptX HD at 48 kHz only from a 44.1 kHz Windows format, where
  earlier drivers fell back to SBC).
- **Best-quality defaults for new devices:** new devices now start LDAC at HQ
  (was SQ) and AAC at up to 320 kbps CBR (was the receiver's maximum with VBR),
  with automatic quality stepping down only under congestion. SBC stays at the
  receiver's maximum bitpool and aptX HD stays ahead of aptX, as before. Saved
  settings of existing devices are never replaced.
- **Real headset delay.** A receiver's delay report is now used even when delay
  reporting was not negotiated. The EDIFIER MR5 reports about 364-396 ms on LDAC,
  so its end-to-end estimate went from 209 ms (a default guess) to about 401 ms,
  which helps players keep picture and sound in sync.
- A stall long enough to trim the buffer twice no longer causes a click.

**Control panel and command line (application 0.1.0.36)**

- **Listening profile** on the **Transport** tab: **Music** (150 / 450 ms, rides
  out radio hiccups without lowering quality), **Balanced** (60 / 250 ms, the
  default) and **Low latency** (30 / 120 ms, video and games), or Custom. A profile
  applies while playing, without interruption. Command line:
  `pna2dpctl set -d N latency.profile=music|balanced|low`; settings export and
  import name the profile.
- Presets follow the new defaults: **Best quality** keeps the receiver's maximum
  SBC bitpool and uses Music buffering; **Driver defaults (best quality, balanced
  buffering)** replaces "Balanced (driver defaults)".
- **Status** has a **Windows rate** row, for example "48000 Hz, converted to 44100 Hz"
  or "44100 Hz, no conversion", and the flag **rate converted**; `pna2dpctl status`
  shows "44100 Hz (Windows 48000 Hz, converted)" on its format line. The Status values
  are wider so that none is cut off, and the Driver line shows the four-part version.
- The sink delay reads "N ms reported by the headset" or "not reported; a
  per-codec default is assumed"; `pna2dpctl status` also notes a report received
  without delay-reporting negotiation.
- An idle, connected receiver shows as **Connected** (since v0.1.0.34).

The full record, with measurements, simulations and review findings, is in
[maximum audio quality](https://github.com/patnawa/PN-A2DP/blob/v0.1.0.36/docs/20-max-audio-quality.md).

## Install or upgrade

- **Stop playback and close the control panel before installing.** If audio is
  playing, Setup leaves the old driver loaded until you restart Windows. With
  playback stopped, the v0.1.0.36 driver installed without a reboot in testing
  (over the intermediate 0.1.0.22 build; an upgrade from v0.1.0.34 was not tested).
- **Existing devices keep their saved settings**, including an LDAC SQ ceiling.
  To move a device to the new best-quality defaults, use **Auto quality + codecs**
  (Codecs or Adapter tab, or `pna2dpctl auto`) or the **Best quality** preset, or
  select HQ on the **LDAC** tab.
- **Choose the sound format in Windows:** **Sound > your device > Properties >
  Advanced > Default Format** (for example 24-bit, 44100 Hz for most music, or
  48000 Hz). Then close and reopen the applications that play sound. Chromium-based
  browsers such as Brave keep their audio stream open while paused, so the new
  format takes effect only after that application reopens its stream.
- For music, try the **Music** listening profile on the **Transport** tab. Keep
  **Balanced** or choose **Low latency** for games and calls.
- While PN-A2DP is installed, a **newly paired** Bluetooth speaker or headphone binds
  to the PN-A2DP driver automatically. Use **Driver > Use Windows mode** to move it
  back to Microsoft's driver.
- If the codec host service restarts during playback (Setup restarts it), the driver
  falls back to SBC and several seconds of audio can drop. The better codec returns
  at the next playback start.
- For the EDIFIER MR5, pair the classic "EDIFIER MR5" entry, not "EDIFIER BLE", which
  carries no audio.

## Test Mode installation

Read the [complete setup and recovery guide](https://github.com/patnawa/PN-A2DP/blob/v0.1.0.36/docs/17-test-mode-release-guide.md)
before changing boot settings. These steps reduce Windows protections and are for
development testing. If device encryption/BitLocker is enabled, prepare the
recovery key and follow the PC's firmware-change procedure.

1. Verify installer/certificate SHA-256 values against `SHA256SUMS.txt`.
2. For **this PN development build**, prepare **Secure Boot OFF** and **Memory
   Integrity OFF**. Use Windows mode if you want to keep the normal protections.
3. In administrator PowerShell, run `bcdedit /set testsigning on`, then **restart
   manually**. The setting must be active in the running session.
4. Inspect `PN-A2DP-Test-Certificate.cer`. Its SHA-1 thumbprint must be
   **`12EE1EAE30E0DEACCFB2870C393D3C148B1E210E`** and it must have no private key.
   This is the same certificate as v0.1.0.30 and v0.1.0.34; if you already trust it,
   you do not need to import it again. Otherwise, if you intend to trust it for
   testing, run these commands from the download folder in administrator PowerShell:

   ```powershell
   certutil -addstore Root .\PN-A2DP-Test-Certificate.cer
   certutil -addstore TrustedPublisher .\PN-A2DP-Test-Certificate.cer
   ```

5. Stop playback, close the control panel and launch:

   ```powershell
   .\PN-A2DP-0.1.0.36-testmode-setup.exe --allow-test-driver
   ```

6. Keep the protected Program Files destination and select the receiver(s) to
   switch. After any requested restart, check the Driver requirements, select the
   receiver in Windows Sound, choose its Default Format and use **Check my audio**.

Setup does not enable Test Mode, import trust or restart Windows automatically.
Adding a certificate or accepting an installer warning does not make this driver
load in normal Windows mode. The Memory Integrity-off requirement is specific to
this validated PN development configuration; it is not a universal rule for every
test-signed driver.
[Microsoft Test Mode guidance](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/the-testsigning-boot-configuration-option),
[test-certificate guidance](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/installing-test-certificates).

**To leave Test Mode:** switch every PN device to **Driver > Use Windows mode**
or uninstall PN-A2DP first. Confirm Windows-driver playback, then run
`bcdedit /set testsigning off` as administrator and restart. Restore Secure Boot,
Memory Integrity and any suspended BitLocker protection. The full guide gives
the exact commands for removing only this development certificate.

ApiValidator, the AddressSanitizer test builds, the independent SBC and plugin decoders,

## Known limitations

- Not tested on hardware: the Sony CMT-SBT40D on this driver; SBC, AAC and aptX
  through the converter; 88.2 / 96 kHz Windows formats; the 48 to 44.1 kHz switch
  during playback; pause and resume on a converted stream; the auto-start case (a
  reconnect configured at 48 kHz before a first 44.1 kHz playback must reconfigure);
  a 2.4 GHz interference session with any profile; the Low latency profile's
  behaviour on a receiver; the new-device defaults on a freshly paired receiver;
  the Transport tab's selector and preset list on a real display; an upgrade from
  v0.1.0.34; long sessions; sleep/wake; Driver Verifier and HLK; Secure Boot or
  Memory Integrity on.
- A Windows format change reaches an application only when it reopens its audio
  stream; some applications (for example Chromium-based browsers) must be closed and
  reopened.
- The converter does not convert from 32 or 16 kHz, from 176.4 / 192 kHz, or up to
  88.2 / 96 kHz; those cases select another codec or renegotiate, as before.
- Under heavy congestion, dual-channel SBC can fall to its lowest step (bitpool 8,
  about 132 kbps), which sounds distorted.
- No limiter or headroom: 0 dBFS music can clip in the receiver's decoder.
- aptX's own high-frequency overload is codec-inherent.
- A codec-host restart during playback drops several seconds of audio.
- `pna2dpctl trace` and `sbc_capture` need an elevated prompt.
- Also not verified: AAC and aptX-family receivers, SBC on the MR5, a confirmed
  physical power-cycle recovery, receiver-initiated and multipoint flows, other
  adapters, LDAC independent decoding and production signing. Codec source
  inclusion does not establish patent clearance or product certification.

## Checksums

`SHA256SUMS.txt` lists the SHA-256 of every asset, and `release-manifest.json`
records the application and driver versions, the certificate thumbprint and the
source revision. Compare a download before running it:

```powershell
Get-FileHash .\PN-A2DP-0.1.0.36-testmode-setup.exe -Algorithm SHA256
```

Report the version, receiver/adapter model, Windows Default Format and
reproduction steps when reporting a problem. **Quality > Export diagnostics**
produces an allowlisted local report; review it before sharing. Neither clean
transport counters nor encoder tests prove universal sound quality or receiver
compatibility.
