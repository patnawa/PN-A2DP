# PN-A2DP v0.1.0.34 — experimental prerelease

**Application 0.1.0.34 · custom driver 0.1.0.21 · Windows x64**

Choose **Windows mode** for use without Test Mode. The separate **Test Mode**
package contains a self-signed development kernel driver; it is **not a
Microsoft-signed production release**. It is signed with the same development
certificate as v0.1.0.30. PN-A2DP applications and installers currently have no
public Authenticode publisher signature and may show a reputation warning.

## What's new

**Control panel**

- **Connect** and **Disconnect** buttons under the device list, for receivers on the
  PN driver or the Windows driver. They send the same request as Windows Settings.
  The command line has `pna2dpctl connect|disconnect` and
  `pna2dpctl windows connect|disconnect`. Pairing and removing receivers stay in
  Windows Settings > Bluetooth & devices.
- New tab order: Status, Quality, Codecs, SBC, AAC, aptX, LDAC, Transport, Headset,
  Adapter, Driver (Windows mode: Audio, Quality, Driver). A device opens on its first
  tab.
- The panel opens on the receiver you are listening to: the Windows default output
  first, then a streaming one, then a connected one.
- An idle, connected receiver is shown as **Connected** (it was "Discovering").
- **SBC XQ** checkbox on the SBC page (default off). It never streams below plain
  dual channel: on receivers that advertise bitpool 53 it gives 672 kbps at 48 kHz
  (by design; not yet tested on a receiver).
- More status detail: the Status page shows receiver-suspended, unreachable and 2:1
  rate-conversion flags, and `pna2dpctl stats` adds counters for starved packets, ring
  overflows and codec-host dropped blocks.

**Driver 0.1.0.21**

- Windows Settings' own **Connect** / **Disconnect** now work for PN-A2DP receivers.
  Earlier PN drivers rejected that request.
- Connection handling: a receiver that suspends the stream is respected, failed
  setups retry with back-off, a stalled link is probed before the stream is dropped,
  and receiver-started sessions and command collisions are handled more carefully.
- Sound: volume and mute changes ramp instead of stepping; pauses, resumes, gaps and
  latency trims fade instead of cutting; the start of a sound after an idle pause is
  delayed instead of cut off; SBC takes 24-bit input; AAC gets dither and codes up to
  19-20 kHz at higher bitrates; aptX packets carry about twice the audio, up to the
  media MTU or 160 codewords.
- Codec host: a failing host is quarantined for a while and the better codec returns
  automatically, instead of staying on SBC; LDAC is refused on a media MTU below
  679 bytes instead of failing repeatedly.
- Security: the codec-host requests need LocalSystem, and the trace and SBC sample
  need an elevated prompt. The control panel still runs unelevated.
- Builds with warnings as errors, Spectre mitigation and CET compatibility; every
  build runs ApiValidator and InfVerif.

The full record, including the review process and every changed behaviour, is in
[driver review fixes](https://github.com/patnawa/PN-A2DP/blob/v0.1.0.34/docs/18-driver-review-fixes.md).

## Install or upgrade

- **Stop playback before installing.** If audio is playing, Setup leaves the old
  driver loaded until you restart Windows.
- Close the control panel first. Existing codec settings are kept on upgrade.
- While PN-A2DP is installed, a **newly paired** Bluetooth speaker or headphone binds
  to the PN-A2DP driver automatically. Use **Driver > Use Windows mode** to move it
  back to Microsoft's driver.
- If the codec host service restarts during playback (Setup restarts it), the driver
  falls back to SBC and several seconds of audio can drop. The better codec returns
  at the next playback start.
- For the EDIFIER MR5, pair the classic "EDIFIER MR5" entry, not "EDIFIER BLE", which
  carries no audio.
- A new receiver starts with LDAC at SQ; choose **Auto quality + codecs** or the LDAC
  tab for HQ.

## Test Mode installation

Read the [complete setup and recovery guide](https://github.com/patnawa/PN-A2DP/blob/v0.1.0.34/docs/17-test-mode-release-guide.md)
before changing boot settings. These steps reduce Windows protections and are for
development testing. If device encryption/BitLocker is enabled, prepare the
recovery key and follow the PC's firmware-change procedure.

1. Verify installer/certificate SHA-256 values against `SHA256SUMS.txt`.
2. For **this PN development build**, prepare **Secure Boot OFF** and **Memory
   Integrity OFF**. Use Windows mode if you want to keep the normal protections.
3. In administrator PowerShell, run `bcdedit /set testsigning on`, then **restart
   manually**. The setting must be active in the running session.
4. Inspect `PN-A2DP-Test-Certificate.cer`. Its SHA-1 thumbprint must be
   **`12EE1EAE30E0DEACCFB2870C393D3C148B1E210E`** and it must have no private key.
   This is the same certificate as v0.1.0.30; if you already trust it, you do not need
   to import it again. Otherwise, if you intend to trust it for testing, run these
   commands from the download folder in administrator PowerShell:

   ```powershell
   certutil -addstore Root .\PN-A2DP-Test-Certificate.cer
   certutil -addstore TrustedPublisher .\PN-A2DP-Test-Certificate.cer
   ```

5. Stop playback, close the control panel and launch:

   ```powershell
   .\PN-A2DP-0.1.0.34-testmode-setup.exe --allow-test-driver
   ```

6. Keep the protected Program Files destination and select the receiver(s) to
   switch. After any requested restart, check the Driver requirements, select the
   receiver in Windows Sound and use **Check my audio**.

Setup does not enable Test Mode, import trust or restart Windows automatically.
Adding a certificate or accepting an installer warning does not make this driver
load in normal Windows mode. The Memory Integrity-off requirement is specific to
this validated PN development configuration; it is not a universal rule for every
test-signed driver.
[Microsoft Test Mode guidance](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/the-testsigning-boot-configuration-option),
[test-certificate guidance](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/installing-test-certificates).

**To leave Test Mode:** switch every PN device to **Driver > Use Windows mode**
or uninstall PN-A2DP first. Confirm Windows-driver playback, then run
`bcdedit /set testsigning off` as administrator and restart. Restore Secure Boot,
Memory Integrity and any suspended BitLocker protection. The full guide gives
the exact commands for removing only this development certificate.

## Validation

**Software.** `verify.ps1 -Sign -Sanitize -Interop` passed all **34** checks:
**57,229** core checks (26,199 at v0.1.0.30), also under AddressSanitizer;
50,000 malformed packet inputs; a new end-to-end audio-quality harness with
**977** jobs and **0** defect flags (one known issue, below, measured within its
recorded bounds); FFmpeg independent decoding of SBC **19/19** and AAC/aptX/aptX
HD/aptX LL **28/28**; 72 audio-health checks; zero driver compiler warnings in
Release and Debug; static analysis at its baseline (all warnings in SDK/WDK
headers); ApiValidator and InfVerif pass. LDAC has no independent decoder test.
Before release, the changes went through a full code review, five adversarial
review rounds (39 defects fixed), an audio-quality review (31 issues fixed) and a
review of those fixes.

**Hardware** (Windows 11, Qualcomm FastConnect 7800, one PC):

| Receiver | Driver | Result |
|---|---|---|
| Sony CMT-SBT40D (SBC only) | 0.1.0.19 | SBC 48 kHz dual channel, **672 kbps**; 15-second check without transport errors; three reconnects of about 2.4 s; saved volume stable |
| EDIFIER MR5 (SBC + LDAC) | 0.1.0.20 | LDAC SQ 660 kbps passed; LDAC **HQ 990 kbps** for 30 s with 0 drops or write failures; three reconnects of about 0.3 s; owner heard no crackle |
| Development PC | 0.1.0.21 | Installed without reboot with playback stopped; Connect / Disconnect owner-tested and reported working (no automated log) |

The released driver 0.1.0.21 adds the Connect / Disconnect fix to the builds measured
above; its playback was not re-measured, and the Sony was not re-tested after
0.1.0.19. This is the first PN-A2DP release with a non-SBC codec (LDAC) played on a
physical receiver.

## Known limitations

- Under heavy congestion, dual-channel SBC can fall to its lowest step (bitpool 8,
  about 132 kbps), which sounds distorted.
- No limiter or headroom: 0 dBFS music can clip in the receiver's decoder.
- AAC at 88.2/96 kHz (only with **Transport > Expose all sample rates**) uses more air time at the same
  audio bandwidth.
- aptX's own high-frequency overload is codec-inherent.
- A codec-host restart during playback drops several seconds of audio.
- `pna2dpctl trace` and `sbc_capture` need an elevated prompt.
- Not verified: AAC and aptX-family receivers, SBC on the MR5, sleep/wake, a confirmed
  physical power-cycle recovery, receiver-initiated and multipoint flows, other
  adapters, LDAC independent decoding, Driver Verifier, HLK and production signing.
  The repository's CI workflow is manual-only and has not run yet. Codec source
  inclusion does not establish patent clearance or product certification.

## Checksums

`SHA256SUMS.txt` lists the SHA-256 of every asset, and `release-manifest.json`
records the application and driver versions, the certificate thumbprint and the
source revision. Compare a download before running it:

```powershell
Get-FileHash .\PN-A2DP-0.1.0.34-testmode-setup.exe -Algorithm SHA256
```

Report the version, receiver/adapter model and reproduction steps when reporting
a problem. **Quality > Export diagnostics** produces an allowlisted local report;
review it before sharing. Neither clean transport counters nor encoder tests prove
universal sound quality or receiver compatibility.
